# Composable meta-widgets

Meta-widgets organize information and actions around records rather than adding a second data store. Examples include summaries, state controls, relationships, workflow steps, and supporting panels where their registered contracts provide them.

Bind each widget to declared fields, queries, operations, or contextual records. Distinguish base Entry fields from custom fields. A field's absence or a failed source needs an honest unavailable state.

Actions follow their operation, policy, and staging contract. Showing an action is not authority to invoke it. Reuse shared named reference and file presentation rather than rendering opaque IDs.

Choose widgets from the live palette and validate their supported config. See [components](UI_COMPONENTS_GUIDE.md), [regions](REGION_SYSTEM.md), and [App Home](../backend/app-home.md).
