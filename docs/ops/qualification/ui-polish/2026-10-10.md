# UI polish — 10 October 2026

Scope: App icons/logos, quieter metadata, stable authentication artwork, manual feed announcements, keyboard and responsive refinements. Existing Integral split-square geometry is preserved.

## Implementation contract

- App identity is optional entity metadata: a built-in icon key or a bounded inline raster logo. Uploads resize to 256 pixels; stored logos are limited to 128 KB. SVG and remote image URLs are not accepted. Existing Apps fall back to initials without a migration.
- Icons appear in the Apps index (56 px), App title (64 px), Home recent Apps, installed-App manager and pinned navigation (28 px). Reordering uses a dedicated button beside the navigation link, with keyboard sorting.
- A manual feed post is a reviewed announcement in a chosen writable, workspace-authored track with an existing Post type. It links to the original rather than copying the source body, fields or attachments. Installed-App generic-query restrictions remain intact. The destination track's permissions govern the announcement; the source entry's permissions still govern the source.
- Authentication artwork uses viewport-relative height independent of the adjacent form. Equal desktop grid columns center the hero and form symmetrically around the viewport midpoint across all authentication variants. Mobile headings use the smaller display scale. Secondary descriptions and context summaries use the secondary body scale; primary entry content retains its existing scale.

## Invariants preserved

- I-GRAPH-01 / I-GRAPH-02: no new entity type or detached record. App creation and feed entry creation retain the existing rooted graph creation paths.
- I-ROLE-01 and workspace scope: logo changes use existing app.create/app.update authority; announcements use entry.create in the selected track. Client eligibility is an affordance, not an authorization grant.
- I-SUBSTRATE-01 / I-EXT-01: generic presentation metadata and publication controls contain no domain-App names or imports.
- I-HOOK-01: no domain trigger behavior is introduced. Announcement creation uses normal entry validation and hooks.
- Audit/change-event semantics: installed-App identity is assigned during install before its lifecycle event; updates retain the canonical App update event.
