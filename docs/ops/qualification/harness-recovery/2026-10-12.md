# Failed-turn recovery and non-admin App authority — 12 October 2026

## Reported behavior and reproduced causes

The supplied screenshots show a provider rejection after several successful
model calls, followed by a reconciliation error when the user asks to retry.
They establish the user-visible sequence; they do not identify the provider's
internal reason for rejecting the fifth call.

The transport previously recorded every SDK exception as `outcome_unknown`.
Recovery admitted an unknown physical request only when its previous run was
cancelled. A scoped failed run with settled tools therefore remained blocked.
Regression tests reproduce that blocker before the patch.

The access review correctly withholds App collaborator directories from
ordinary readers and editors while returning their own `caller_role`. The App
API client discarded that field, and the page derived editing rights from the
empty directory. The page-level regression reproduces a shared App editor
receiving read-only dashboard controls with the original role inference.

## Changes and preserved boundaries

- Failed and cancelled runs can accept a new user turn after their original
  tool effects reconcile. Completed tool results remain in history; no old
  physical model request or tool effect is automatically retried.
- Explicit SDK rejections before a response are failed attempts. Timeouts,
  interrupted streams and network uncertainty keep their unknown accounting.
  No provider price, usage or completed receipt is invented.
- Running or foreign runs, unresolved mutations, pending approvals and invalid
  checkpoint pointers retain their existing refusal paths.
- The durable worker explicitly closes provider streams in their owning task.
  Timeout during event persistence previously left cleanup to an async-generator
  finalizer in another task, which cannot safely reset the harness's context
  tokens. A deterministic PostgreSQL test reproduces that task mismatch before
  the patch and verifies owning-task cleanup afterwards. The existing 50 ms
  timeout test retains its deadline; its fixture now records closure while
  paused at the first yield as well as cancellation during its later await.
- The App page uses the server's own-caller role independently of directory
  visibility. Editors regain dashboard editing; commenters and viewers remain
  read-only. Older payloads that omit the role retain the existing fallback.
- Full App collaborator responses now include the same caller-role metadata.

This repair preserves I-ROLE-01/02 and I-ACCESS-01 (current role boundaries and
private directories), I-WORK-01/02/05/07 (fences, effect identity, approvals and
physical-dispatch accounting), and I-GRAPH-01/02 and I-SUBSTRATE-01/I-EXT-01
(no new graph participants, domain behavior or App imports).

continuation, SDK rejection/stream accounting, provider streaming and directory
authority: 172 checks passed.

without rewriting unknown model accounting, together with the existing
running-request replay refusal. Frontend production compilation passes. The
initial full frontend run had two timing-sensitive failures under concurrent

The stale-environment run is not passing qualification.

The final PostgreSQL worker and directory suite passes all 22 cases, including
process death, interrupted physical dispatch, preservation of partial output,
idempotent terminalization, persisted failed-run continuation and owning-task
stream cleanup. The disposable database container was removed afterwards.

Final scoped substrate guards, pre-commit checks, pinned formatting/lint and
backend typing pass. The final source also passes reproducible wheel building
and independent wheel import. The complete non-smoke backend partition passes
with the repository's normal domain/slow exclusions and PostgreSQL skips.
