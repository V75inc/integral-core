# JV Spatial transaction and database-log changes

JV Spatial now provides transaction-scoped `find_one`, `find_ids`, `count`,
`find_many`, keyset iteration, and incident-edge counting. PostgreSQL uses
native same-connection projections and aggregates; Mongo transactions use the
shared transaction contract and preserve the session. Graph transactions use
an isolated, context-bound identity map so preloaded objects cannot escape the
transaction or expose uncommitted changes through the process cache.

Successful database operations, including slow ones, no longer emit observation
logs on any backend. Failures remain structured ERROR records. The configured
slow-query threshold only increments the slow-operation metric. Core no longer
has a per-logger level workaround; its ordinary DB metrics recorder remains
enabled.

Validation performed:

- JV Spatial full suite passed after the log expectation was changed to metrics.
- JV Spatial PostgreSQL integration suite: 39 passed against the local PG
  service, including held-connection reads, bootstrap/rollback, and tenant RLS.
- JV Spatial focused Mongo transaction, cache-isolation, and log tests passed.
- Core DB logging regression tests: 6 passed against the JV source tree; the
  independent package-pin metadata check passed against Core's installed wheel.
- Core focused PostgreSQL transaction, authorization, admin, tool, track
  inheritance, and listing/pagination suites passed sequentially.
- Core CI-faithful backend smoke gate (`make verify-ci`) passed with JV source
  injected. A full Core backend run was attempted before the logging tests were
  aligned with the new policy; it reported only those four outdated test
  expectations and was not rerun in full.

At this record's original qualification time, Core's package pin remained `jvspatial==0.2.1`; these upstream changes require a
new JV Spatial release before a clean Core install can consume them. No commit,
push, or deployment is included in this qualification.

The published 0.2.2 upgrade is covered by the [rc18 follow-up](../core-rc18/2026-10-13.md).
