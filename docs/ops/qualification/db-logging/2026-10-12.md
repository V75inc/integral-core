# Published jvspatial 0.2.1 logging verification

Core's dependency metadata and `backend/uv.lock` pin `jvspatial==0.2.1` from
PyPI. `uv lock --upgrade-package jvspatial` changed only that package and its
Core requirement. `uv sync --frozen --extra dev --extra test` installed the
published wheel; runtime metadata confirms 0.2.1 under site-packages, rather
than the jvspatial development checkout. `uv lock --check` passes.

Core's default `DB_OPERATION_LOG_LEVEL` is now INFO. The earlier WARNING
suppression workaround is unnecessary: ordinary successful operations emit
DEBUG upstream, while slow and failed operations emit WARNING. DEBUG remains
an explicit tracing option. Existing hosts with an explicit WARNING setting
remain quiet and retain warnings; update that setting to DEBUG for tracing.

The six logging regressions use the public `create_database` factory and real
JSON database queries. They prove published package/version metadata, quiet
routine `db.find` calls at INFO with Core's metrics intact, slow-query WARNING,
ERROR visibility, fast failed-query WARNING and exception propagation, DEBUG
structured tracing, and quiet upstream INFO behavior with Core's logger
configuration bypassed. A forced database failure is injected only in the
failure test; normal queries are not mocked.

Validation:
- Logging and boot-guard tests: 18 passed.
- Access directory, account timezone, and SDK transport compatibility: 58 passed.
- A console probe using the same standard logging setup as Core confirmed
  quiet INFO queries, visible DEBUG tracing, and visible slow-query WARNING.
- Frozen lock validation, logging/config lint, all substrate guards, pre-commit
  checks (including mypy), and pinned formatting checks passed.
- `make verify-artifact` passed, including byte-for-byte reproducible wheel
  builds and source-independent packaged imports using prepared dependencies.

This is bounded dependency/logging qualification. At that dependency-update snapshot the full release suite had not been
rerun and no Core commit or push had been performed. Subsequent commit/PR
validation is recorded in the [isolated PR verification](../core-recovery-pr/2026-10-12.md).
No running-service restart or deployment is included. The reproducible artifact gate is not a fresh public dependency install
or production logging/deployment proof.
