# Review, jb/main, 2026-09-28

**Reviewed by**: Opus (author model unknown)
**Scope**: 17 files, branch vs `main` (merge-base `abe1ced`), 4 commits, working tree clean
**Verdict**: Blocked

## Summary

This change lands the hosted base-plan subscription lock: a `HostedSubscription`
projection (`Object`, per I-GRAPH-02), a status/operator-upsert API, a Starlette
middleware that refuses writes when a workspace's plan has lapsed, manual-vs-provider
precedence on entitlements, and a paywall explanation in the Manage Apps dialog. The
open-source posture is handled well — every new path early-returns when
`INTEGRAL_SUBSCRIPTION_REQUIRED` is false, no Stripe import or price id appears in
Core, and the provider refetch is a registration callback so Core never imports the
Business package. Typecheck is clean and both new test files pass.

The enforcement layer is where it breaks down. `BillingLockMiddleware` decides *which
workspace is being billed* from the raw client-supplied `X-Integral-Scope` header,
without checking it against the caller or against the resource the request actually
writes — that is simultaneously a paywall bypass and a false-positive 402 on
cross-workspace flows. Worse, the middleware is registered *outside* the auth
middleware, and the code it calls performs entitlement revocations and App pauses, so
an unauthenticated request can trigger writes. Two blockers, three majors.

## Blockers

### 🔴 Billing subject is taken from an unvalidated client header, `backend/app/middleware/billing_lock.py:68`

**Problem**: `dispatch()` resolves the workspace to bill from
`request.headers.get("x-integral-scope")` and nothing else. It never verifies (a) that
the caller is a member of that workspace, or (b) that the header matches the workspace
the request is actually about — every write endpoint derives its real target from the
URL path or body (`POST /api/entries`, `PATCH /api/tracks/{id}`,
`POST /api/invitations/{token}/accept`), not from this header. AGENTS.md is explicit
that the scope header is a *hint* that `services/request_scope.py` validates against
live membership; this middleware skips that validation entirely.

**Why it matters**: It fails in both directions.

- *Bypass*: a caller whose workspace is locked can send
  `X-Integral-Scope: ws:<id of any workspace with an active plan>` and every write
  goes through — the write still lands in the locked workspace, because the endpoint
  reads the target from the path/body. Any user who belongs to one paying workspace
  can keep writing in all of their lapsed ones. For a change whose entire purpose is
  revenue enforcement, the gate is one header away from being off.
- *False block*: writes that legitimately target a workspace other than the active
  scope are judged against the wrong row. `POST /api/invitations/{token}/accept`
  (`backend/app/api/invitations.py:406`) and `POST /api/shares/redeem`
  (`backend/app/api/shares.py:168`) are the clearest cases: an invitee's header points
  at their own personal workspace, which has no `HostedSubscription` row, so
  `access_for_row` returns `locked` and they get a 402 accepting an invitation into a
  fully paid workspace. Onboarding into a hosted cell is broken.

**Suggested fix**: Do not decide this in path-agnostic middleware. Resolve the billing
subject after auth, from the workspace the request resolves to — reuse
`resolve_workspace_id_from_request` / `services/workspace_resolver.py` so membership is
validated, and enforce in the service layer (or a dependency) where the target
workspace is already known. If a middleware-shaped gate is worth keeping for the common
case, it must at minimum verify caller membership of the header workspace before
trusting it, and must not be the only check.

### 🔴 The lock runs before authentication and mutates data from the request path, `backend/app/middleware/billing_lock.py:75`

**Problem**: `BillingLockMiddleware` is added at `backend/app/main.py:1597`, i.e. after
`TestAuthBypassMiddleware` and after the auth middleware jvspatial installs during
`Server` construction. Starlette runs most-recently-added first, so this middleware
executes *before* any authentication — `request.state.user` is not populated yet. The
call it makes, `workspace_allows_hosted_writes`
(`backend/app/services/hosted_subscription.py:184`), is not a read: on a locked
workspace it calls `pause_lapsed_provider_entitlements`, which iterates entitlements,
calls `revoke_provider_entitlement` → `revoke_entitlement` → `pause_app`
(`backend/app/services/entitlements.py:259`, `:209`).

**Why it matters**: An unauthenticated POST carrying an arbitrary workspace id in a
header causes unbounded `Entitlement.find` queries and, for any workspace whose plan is
locked, entitlement revocation and App pausing. Anonymous traffic should never reach a
code path that writes. It is also a cheap amplification target — each request re-runs
the entitlement scan — sitting in front of every write in the product. The main.py
comment block at `:1588` explains the ordering intent for the other middleware; this one
was inserted into that stack without accounting for where auth sits.

**Suggested fix**: Make the enforcement path strictly read-only — return the access
verdict and nothing else. Leave lapse enforcement to `hosted_billing_reconcile_loop`,
which already calls `enforce_lapsed_hosted_subscriptions` hourly and is the right place
for it. Separately, move the check to run after authentication (a dependency or a
service-layer guard, per the blocker above) so an unauthenticated request cannot reach
it at all.

## Major

### 🟠 A missing scope header means "locked", which shuts off every non-browser write client, `backend/app/middleware/billing_lock.py:71`

**Problem**: When no `ws:` header is present the middleware returns 402 outright. Only
the browser SPA sets that header (injected by the axios interceptor,
`frontend/src/api/client.ts:76`). Nothing else does.

**Why it matters**: With the lock on, this 402s the entire MCP surface —
`POST /api/mcp` is a mounted sub-app wrapped by this middleware
(`backend/app/main.py:1685`) and external MCP clients have no concept of
`X-Integral-Scope`. AGENTS.md and `docs/product/BYOA.md` make MCP the *only* supported
external-agent surface, so hosted deployments would ship with BYOA writes dead. It also
breaks the auth-exempt system-uplink POSTs allowlisted at `backend/app/main.py:1378`
(`/api/agentive/uplink/register-system`, `heartbeat-system`) and any server-to-server
integration. None of this is visible from the unit tests, which only exercise the pure
`request_requires_subscription` helper.

**Suggested fix**: Falls out of the blocker fix — resolve the workspace from the
request's actual target rather than the header, and fail closed only when the target
genuinely cannot be determined. Whatever the resolution, MCP and uplink paths need an
explicit decision and a test.

### 🟠 Unrelated port change breaks the local compose stack, `docker-compose.local.yml:129`

**Problem**: The frontend publish port moves `9006:80` → `9007:80`, but the rest of the
same file still says 9006: the header instructions at `:7` ("Open
http://localhost:9006"), `APP_BASE_URL: http://localhost:9006` at `:83`, and
`JVSPATIAL_CORS_ORIGINS` at `:84`. This has nothing to do with billing.

**Why it matters**: `APP_BASE_URL` is what invitation links, share links and
verification emails are built from, so every generated link points at a port with
nothing on it. Any browser call from `:9007` to the directly-exposed API on `:4002` is
now cross-origin against a CORS allowlist that does not contain `:9007`. It reads like
a local "the port was busy" tweak that got committed.

**Suggested fix**: Revert to 9006, or change all four places together plus the docs
that reference the local compose port.

### 🟠 The invariants this change exists to protect are untested, `backend/tests/test_billing_access.py:1`

**Problem**: The new backend test file covers three pure helpers — `access_for`,
`grace_until_iso`, `request_requires_subscription`, `workspace_id_from_scope_header`.
Everything with branching, I/O or a security consequence is uncovered:

- `upsert_hosted_subscription(from_provider=True)` returning `(existing, False)` against
  a `source=manual` row (`services/hosted_subscription.py:135`) — the headline
  "manual rows must not be overwritten by a payment provider" invariant.
- `grant_entitlement(respect_manual=True)` short-circuit
  (`services/entitlements.py:138`).
- `revoke_provider_entitlement` skipping manual rows
  (`services/entitlements.py:252`).
- The new 403 on `/entitlements/grant` and `/entitlements/revoke` for non-platform-admins
  when the lock is on (`api/entitlements.py:99`, `:129`).
- `BillingLockMiddleware.dispatch` itself — no request-level test, which is precisely
  why the header-trust and ordering blockers above are invisible to the suite.

**Why it matters**: `TESTS = configured`, and per the project's own bar this is
branching, security-relevant logic. A regression in manual-row precedence silently
hands a customer's operator override to the payment provider, and nothing would catch
it.

**Suggested fix**: Add service-level tests for the manual-precedence paths (they need
no HTTP), plus an `authenticated_client` test that drives a write through the middleware
with the lock on for the open / grace / locked / wrong-workspace cases. Consider
`@pytest.mark.smoke` on the permission-shaped ones — `backend/pyproject.toml:183`
names security regressions as exactly what the smoke gate is for, and as written none
of this file runs on a PR.

## Minor

### 🟡 `past_due` with no timestamp grants unbounded grace, `backend/app/services/hosted_subscription.py:64`

`access_for` returns `"grace"` when `past_due_since` is empty or unparseable, forever.
`upsert_hosted_subscription` always fills the timestamp, so Core-written rows are fine —
but the Business package writes this model too, and one row with a missing or malformed
timestamp is permanent free access with no signal anywhere. Prefer treating an absent
timestamp as "grace starts now" and persisting it, or as locked.

### 🟡 Manual-source comparison is case- and whitespace-sensitive where it guards the invariant, `backend/app/services/hosted_subscription.py:135`

`(existing.source or "") == "manual"` here and at `services/entitlements.py:138`, versus
`.strip().lower() in {"", "manual"}` at `services/entitlements.py:252`. A row stored as
`"Manual"` or `" manual"` — plausible from the external writer — passes the guard and
gets clobbered by a provider reconcile. Normalise identically in all three places.

### 🟡 Once set manually, a workspace can never return to provider control, `backend/app/api/billing.py:113`

The operator endpoint hardcodes `source="manual"`, and `from_provider` writes then skip
the row permanently. There is no API to release the pin, so a one-off support override
silently makes that workspace's plan un-reconcilable forever. Add a way to hand the row
back (an explicit `source` parameter, or a delete).

### 🟡 Per-write subscription lookup with no caching, `backend/app/middleware/billing_lock.py:75`

Every gated write does an extra `HostedSubscription.find` round-trip on the hot path.
`PermissionsCacheMiddleware` is the existing precedent for caching this class of
per-request check; a short TTL cache keyed by workspace would remove it. Not urgent, but
this sits in front of every write in the product.

### 🟡 Unbounded scan in the hourly reconcile, `backend/app/services/hosted_subscription.py:237`

`HostedSubscription.find({"context.status": status})` loads every `past_due`, `canceled`
and `incomplete` row into memory, then serially runs an entitlement scan per workspace.
On a hosted cell of any size that is the whole lapsed population every hour. Page it, or
filter to rows that actually crossed out of grace since the last tick.

### 🟡 The 402 short-circuit skips the security-header and CORS middleware, `backend/app/main.py:1597`

`SecurityHeadersMiddleware` is added before `BillingLockMiddleware`, so it is *inside* it
and never runs on the short-circuit response; the same applies to the CORS middleware
jvspatial installs at `Server` construction. `RateLimitMiddleware` has the same property
today, so this is consistent with existing behaviour rather than new — but a 402 that a
cross-origin SPA cannot read is a real failure mode if the frontend is ever served from
a different origin than the API.

### 🟡 Catalog fetch failures silently un-gate every add-on row, `frontend/src/api/billing.ts:29`

`status` and `catalog` swallow all errors to `null`. When `catalog` is null but the base
plan is open, `paywallForSlug` returns "not blocked" for every slug
(`billingAccess.ts:50`), so a transient failure makes paid apps look installable until
the server rejects the install. The server remains the gate, so this is a UX mismatch,
not a hole — but distinguishing "no billing module" (404, expected) from "request
failed" would make the dialog honest. The same applies to a workspace *member* rather
than admin: `/billing/status` is admin-only (`api/billing.py:47`), so members get a 403,
see no paywall, and discover the block only on submit.

### 🟡 Slug comparison normalises one side only, `frontend/src/components/apps/billingAccess.ts:49`

`key` is lowercased and trimmed; `row.slug` and the `requires` entries are compared
verbatim. A catalog slug with different casing silently reports "not blocked". Normalise
both sides, or neither.

### 🟡 The Add button is not disabled while a billing call is in flight, `frontend/src/components/apps/AppManagerDialog.tsx:947`

`addAddon` sets `billingBusy`, but this `Button` reads neither `loading` nor `disabled`,
unlike the Subscribe and Manage-billing buttons at `:499`/`:511`. A double click fires
two `POST /billing/addons` on a payment path. Whether that is harmful depends on the
private module's idempotency, which is exactly why the UI should not rely on it.

### 🟡 Core's frontend now calls endpoints Core does not define

`frontend/src/api/billing.ts` hardcodes `/billing/catalog`, `/billing/checkout`,
`/billing/portal` and `/billing/addons` plus their response shapes
(`billingAccess.ts:6`, `:23`), none of which exist in Core — they only appear when
`INTEGRAL_BILLING_MODULE` registers them. That is a private API contract embedded in the
open-source tree with nothing to keep the two in sync. Consider publishing these shapes
alongside the extension contract (`docs/platform/extension-contract-v1.md`) so a
Business-side change has a visible Core-side counterpart.

## Strengths

- The open-source kill-switch discipline is genuinely well executed. Every new path
  early-returns on `INTEGRAL_SUBSCRIPTION_REQUIRED`, no Stripe symbol or price id
  appears anywhere in Core, and `register_billing_reconcile`
  (`services/hosted_subscription.py:25`) inverts the dependency so Core never imports
  the Business package. This is the hard part of a commercial-fork boundary and it is
  right.
- `HostedSubscription` is correctly an `Object`, not a `Node`, per I-GRAPH-02, and
  mirrors `Entitlement` exactly down to the partial unique index — the model docstring
  states the reasoning rather than leaving a reader to infer it.
- Manual-vs-provider precedence is implemented at the right layer and with explicit
  outcomes: `upsert_hosted_subscription` returns `(row, applied)` and
  `revoke_provider_entitlement` returns a `skipped` reason instead of silently
  no-opping, so a caller can tell "refused" from "done".
- `workspace_id_from_scope_header` deliberately refuses a bare id rather than falling
  back to Personal Workspace, which is the exact trap AGENTS.md warns about — and it is
  tested (`tests/test_billing_access.py:105`).
- Grace-window math is pure with injectable `now` / `grace_days`, and the test checks
  the inclusive boundary, not just the obvious inside/outside cases.
- Conventions are respected throughout: `@endpoint` not `APIRouter`, `JVSpatialAPIException`
  subclasses not `HTTPException`, schemas in `app/schemas/billing.py`, and the flat-param
  POST signature matches the existing `api/entitlements.py` ParameterModelFactory style
  rather than inventing a new one.

## Test coverage

Covered: the grace-window state machine (`access_for`, `grace_until_iso`) including the
boundary; the allow/deny path classification in `request_requires_subscription`; scope
header parsing; and, on the frontend, all five `paywallForSlug` branches. Both new files
pass (`pytest tests/test_billing_access.py` 6 passed, `vitest billingAccess.test.ts`
5 passed) and `tsc --noEmit` is clean.

Uncovered: everything with I/O or an authorization consequence — `upsert_hosted_subscription`
manual precedence, `grant_entitlement(respect_manual=True)`, `revoke_provider_entitlement`,
`pause_lapsed_provider_entitlements`, `enforce_lapsed_hosted_subscriptions`, the new
platform-admin requirement on the entitlement endpoints, and `BillingLockMiddleware`
end-to-end. The middleware gap is the consequential one: both blockers are behaviours a
single request-level test (wrong-workspace header, no header) would have surfaced. The
file also carries no `smoke` marker, so none of it runs on a PR.
