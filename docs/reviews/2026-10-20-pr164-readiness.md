# PR 164 review and merge readiness

Reviewed original head `dd10feae9eb78f744450f3daefb4e202b6216503` against
`main` (`5d0f60553764c1350362e35be002a922064fc400`). There were no issue
comments, reviews or review threads at review time. Existing local preview
and other PR worktrees were preserved; remediation uses `codex/pr164-review`.

## Decision

**Blocked by the backend dependency audit. Do not merge on the basis of the
frame tests or the frontend audit alone.** No audit exception was added and
no dependency constraint was overridden.

## Findings and remediation

1. **Malformed origins could fail frame rendering.** `urlsplit` and `.port`
   raise on malformed brackets, nonnumeric ports and out-of-range ports.
   Omit invalid settings independently, retaining other valid origins.
2. **Parsed host names were not safe CSP source tokens.** Reject controls,
   whitespace, credentials, wildcards, backslashes and CSP/header delimiters;
   allow only explicit HTTP(S) ASCII host sources, strip paths, normalize
   default ports, and deduplicate. International domain names must be
   configured in punycode. IPv6 literals are omitted because CSP host-source
   syntax does not support them; use a DNS name for a separate IPv6 UI.
3. **CI dependency audits failed independently of the frame patch.** Refresh
   certifi `2026.2.25 -> 2026.10.19`, uv `0.12.24 -> 0.13.4`, and
   follow-redirects `1.16.0 -> 1.16.1`. A fresh frontend audit also identified
   Vite launch-editor advisories; update `8.1.2 -> 8.1.6` and its required
   build dependencies. Existing reviewed build-only exceptions are unchanged.
4. **Pillow remains an upstream compatibility blocker.** The frozen backend
   audit still reports eight Pillow 12.3.0 advisories with fix version 13.0.0.
   Core's FastEmbed dependency requires Pillow below 13.0, including the
   latest published FastEmbed 0.9.0. `uv lock --upgrade-package
   'pillow==13.0.0'` fails resolution; narrowing Python support does not remove
   the FastEmbed upper bound. A compatible upstream FastEmbed release or a
   separately qualified embedding-provider dependency change is required.
   Silencing the audit, removing embeddings or overriding the upstream
   contract would not establish merge readiness.

## Preserved boundaries

This remains a package-neutral host change (I-EXT-01). Configuration comes
from trusted deployment settings, never the request Origin. Frame grants
remain signed and scoped; current workspace/App access is rechecked. Sandbox,
script hashes, disabled network access, cache controls and frame-handler-only
security-header relaxation remain in place. The Docker nginx proxy already
has an exact `/api/extension-view-frame` location that suppresses inherited
SPA deny/CSP headers; it preserves the validated handler's CSP. The separate
static-SPA nginx configuration does not proxy API routes. The allowed parent
URL does not grant data or operation access.
