# Integral Core connector extension audit

Source reviewed: `41867b70`, including the staged Web Chat request and receipt code. This is a source audit, not certification of a deployment, provider account, package installer, or the proposed third-party SDK.

## Decision

A connector is a named, versioned product extension, not a single execution engine. Core must own one registration and lifecycle contract while keeping synchronization, outbound MCP calls, and inbound messaging separate at runtime. Outbound agents and Workspace Email keep their distinct execution/authorization models. Adoption into the Connector Library should not silently turn them into channels or grant new access.

Core must not expose an incomplete registration or execute an unregistered connector. Register a package as a unit: a validated descriptor, supported setup schema, runtime adapter for every declared capability, and the lifecycle hooks needed to manage an installation. No duct-tape settings entry, duplicate ID, or browser-only definition. A recognized, admitted package and its installed instances are different things. Temporary failure must never make an installed connector disappear from **Connected**.

| State | Product behavior |
| --- | --- |
| Absent, rejected, structurally incomplete, or incompatible | Not offered for installation and cannot dispatch. Record the validation reason for operators. If a previously installed version loses its adapter, preserve a safe, unavailable management record with no dispatch or sharing. |
| Registered, not installed | Discoverable in the Connector Library to the appropriate audience. Enable **Add** for allowed scopes only when required setup prerequisites can be met; otherwise show a safe reason. |
| Installed but not enabled | List under **Connected**; configure, validate, enable, or remove as authorized. Never serve public traffic on this state. |
| Installed but unavailable | Keep it visible; retain disable/remove, and safe recovery controls where supported. No traffic, active links, or key issuance. |
| Active | Requires current provision, authorization, configuration revision, healthy adapter and relevant capability-specific checks. **Configure** uses the same install schema plus safe provider-specific actions. Share controls only for admitted channel presentations. |

## Findings and rollout gates

| Priority | Evidence and consequence |
| --- | --- |
| Release gate | `backend/app/connectors/catalog_loader.py` reads Core's YAML catalog, accepts only sync/MCP and sets `vetted` for bundled entries. `backend/app/services/connectors/registry.py` and `backend/app/agentive/connectors/registry.py` dispatch different runtime types; neither is connector package discovery. `backend/app/services/operational_model_plugins.py` has trusted plugin admission for other extension kinds, not connector packages. The Python SDK has no versioned connector entry point/contract. A third party cannot drop in a new connector with a full supported lifecycle today. |
| Release gate | Current MCP and native sync credential storage are not equivalent. The connector node encrypts MCP auth state; native sync paths still use legacy inline auth state. The sync failure path records raw provider exception text, and some MCP mount recovery paths persist raw exception text despite having a scrubber in other paths. Require Core-owned scoped secret handles, a reversible legacy migration, and categorized redacted diagnostics before broadening native connector admission. This is a source finding, not evidence of a reported leak. See `backend/app/agentive/services/connector_registry_node.py` and `backend/app/services/connectors/sync_runtime.py`. |
| High | `frontend/src/features/settings/connectors/connectorDefinitions.ts` stitches server packages together with frontend-only WhatsApp and Custom MCP descriptors. `ConnectorsSection.tsx` separately probes the Web Chat route and renders a readiness-gated section outside the regular catalogue/installed-instance lifecycle. Web Chat has no generic package/instance registration and no mounted visitor host. A green component test cannot qualify the connector or a live response. |
| High | Catalogue discovery/preview currently requires the workspace-admin helper, while catalog installation has a per-user member flow. Match discovery to permitted install scope without allowing workspace-wide grants or exposing secrets. Verify shared install concurrency: the current lookup-then-create approach did not show an atomic uniqueness guarantee in the audited path. No duplicate install was reproduced. See `backend/app/agentive/api/connectors.py`. |
| High | Install and Configure do not share one contract: curated install uses metadata, but the generic edit modal allows raw auth-state JSON and free-text fields while Gmail/QuickBooks and WhatsApp take separate paths. Custom MCP can render a raw stdio option that production rejects; a mocked success test does not qualify it. The official MCP registry browser has no call site in the audited UI. Use safe, Core-owned schema components and an allowlist of trusted setup actions; do not require or load arbitrary frontend code. |
| High | Disable, uninstall, token cleanup, worker drain, upgrade, and rollback are not one tested cross-adapter lifecycle. Existing sync leases and MCP shutdown/credential cleanup are useful, but some cleanup is best effort. Persist desired state separately from current health; revocation must take effect before external cleanup retry. |
| High | Web Chat still needs authenticated visitor-session issuance, mounted host and tool-free inference against a pinned published identity, retrieval/history isolation, rate budgets and bounded retention/recovery. Its PostgreSQL receipt does prevent a retry from taking a second fence; unresolved attempts deliberately do not auto-reclaim. Public link, JS embed, and optional API credentials must derive from the same connector instance without sharing a browser secret or inferring authorization from link visibility. |

Preserve and test existing distinctions: signed/verified WhatsApp ingress; the MCP curated read-only allowlist and proposal/approval gates; canonical sync provenance, conflicts, checkpoints and leases; explicit scope and credential ownership. Avoid replacing these with one permissive generic `execute` hook.

## Proposed v1 contract

1. **Package admission.** Stable namespaced ID, package and Core API compatibility versions, publisher/provenance, manifest digest, requested capabilities, configuration schema, supported scope/cardinality, supported lifecycle/health hooks, and independently validated runtime entry points. Reuse Core's signed package admission patterns after review. Python entry points can be a discovery mechanism for approved distributions; discovery or a signature alone does not authorize module import or operation. Default deny. Untrusted code belongs behind a restricted process or remote protocol, never inside the Core process, and secret/network/file grants must be explicit and scoped.
2. **Lifecycle.** Persist a durable instance identity distinct from its definition and published profile, with atomic cardinality, expected version, and replay-safe install/upgrade/removal operations. Use the same authorization and status projection across API, UI and workers; a manifest cannot grant itself privileges. Core mediates schema validation, secret references, request routing, tenant identity, timeout/budget, health/error codes, logging and audit receipts. Hooks do adapter work with a narrow context: validate/setup, probe, enable/disable, refresh, upgrade/migrate and remove. Require only the hooks appropriate for each declared capability. Do not run arbitrary hook names from browser inputs.
3. **Presentation.** Drive Library, Connected, Add and Configure from the same admitted descriptor and instance projection. Provide renderers for ordinary fields, secrets, OAuth and vetted setup actions. Never show an active badge solely because enabled is true. Return host-issued share options only when authorized and active. Browser embed uses a short-lived scoped visitor session, not a repurposed API key. Server API credentials are optional, scoped, rate-limited, revocable and not shown again after issuance.
4. **Conformance.** Supply a maintained sample package outside the Core tree and a versioned test kit. Test rejected/malformed/duplicate registrations, no-Core-edit installation, workspace/per-user authorization and cardinality, concurrent mutations across workers, health failure and recovery, upgrade/rollback, disable/uninstall and revocation, tenant isolation, redaction, and adapter-specific behavior. Run tests against actual Core routes as well as unit fixtures.

## Migration, not a rewrite

- First agree on the manifest/lifecycle types and shared UI projection. Add one externally packaged conformance adapter that does not touch real accounts. Prevent new channel-specific settings islands. The generic registration and its integration into the API/settings are separate milestones; do not present contract tests as shipped SDK support.
- Adapt existing curated sync and MCP packages in place, preserving stable IDs, per-user connections and OAuth/credential continuity. Align catalogue authorization and replace the raw edit path as adapters qualify. Migrate the native secrets and diagnostic paths before opening credential-bearing drop-ins.
- Qualify one inbound package end to end, Web Chat, through the same register/install/Configure path. Test a real response from the selected published profile on an approved isolated host, then the full-page link and exact-origin embed, then opt-in scoped API access and abuse/budget/load tests. Use real revocation and isolation checks; do not use the standalone preview as delivery evidence.
- Move WhatsApp (JV Connect) behind a thin package adapter without changing existing grants or transport semantics, then Custom MCP/remaining exceptions as appropriate. Register future channels only when their adapters are complete. Preserve old IDs and include upgrade/readback, rollback, and removal tests for each adapter.

They illustrate discovery and declarative contribution, not a security or launch approval for Integral.
