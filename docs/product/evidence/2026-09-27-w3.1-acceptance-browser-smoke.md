These local browser observations do not qualify a clean wheel or separately installed App release.

## System and skill improvements identified

1. **Execution receipts:** Separate tool names proposed in the resident work trace from tools that actually reached Core. The failed runs displayed “Using integral_aggregate…” while `claim_provenance.substrate_query_executed` was false. Gate factual answers on a successful read receipt.
2. **Tool availability:** Make skill activation and tool loading explicit to the runtime, with a structured unavailable-tool result. The insights skill now names the exact aggregate procedure, but prose alone did not cause invocation in these runs.
3. **Browser regression:** Keep the focused and uniquely named Track prompts above as browser smoke cases. The host-bound read restores these paths; ambiguous names and unnamed cross-Track aggregates still need an explicit grounded query path before any answer.
