## Enterprise gates beyond package compatibility

1. **Tenant boundary:** Core validates a requested workspace against live
   membership (`backend/app/services/request_scope.py`). It does not currently
   enable jvspatial PostgreSQL RLS. Decide and prove the production isolation
   architecture, including agent, scheduled, extension, and administrator
   paths. If using RLS, derive the tenant from authorized server-side scope,
   require it on tenant tables, and run the application as `NOBYPASSRLS`.
2. **OAuth key custody:** Core enables the jvspatial OAuth authorization server
   (`backend/app/main.py`). The candidate keystore encrypts private RS256 keys
   when `JVSPATIAL_OAUTH_KEY_ENCRYPTION_KEY` is configured, and Core refuses
   production startup without a valid Fernet key. Existing plaintext rows
   rewrap on first use. Protect old backups, provision the key through a secret
   manager, and prove rotation and recovery before an enterprise deployment.
3. **Audit evidence:** Core ChangeEvents are stored in the logging database,
   but a missing log database can leave an event unpersisted. Define which
   events must be durable, monitor failures, prove retention and export, and
   test loss and recovery.
4. **Topology:** Keep `WORKERS` and `WEB_CONCURRENCY` at one until in-flight
   turn admission and websocket fan-out use shared state. Use shared limit and
   session backends where more than one process or host is involved.
5. **Release proof:** Freeze one Core SHA and image digest. Run fresh PostgreSQL,
   deployed browser, restart/replay, restore, and independent App journeys on
   that exact candidate. Record pass/fail and evidence in C6 before rollout.

These are explicit release gates. Passing the source smoke tests cannot close
them. SOC 2 readiness additionally requires operated controls and evidence
for the defined service and audit period.
