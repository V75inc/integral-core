# WP-02.1 Evidence — rooted session contract

`HarnessSession` is defined as a jvspatial Node and is registered in Core's node catalogue. `HAS_HARNESS_SESSION` is a typed relationship from ChatThread to HarnessSession, and `I-HARNESS-01` records the rooting, scope binding, historical-session, checkpoint Object, and production-fencing rules. `ensure_harness_session` validates ChatThread owner/workspace, rejects session-ID collisions, and performs conditional generation update, Node save, and typed edge creation inside one graph transaction. `transition_harness_session` implements suspend/closed/expired/revoked states with active-pointer clearing. Contract tests verify mocked transaction ordering, status retention, authorization denial, and fail-closed behavior when the store lacks transaction support.

The temporary PostgreSQL 14.17 cluster on port 5433 passes `tests/contract/test_harness_sessions_postgres.py`: the session pointer, node, and edge commit atomically; injected edge failure rolls all three back; two independent transactions held at the same compare-and-swap point produce exactly one active generation winner; and `GraphReachabilityWalker` reaches both ChatThread and HarnessSession from Root. Owner-scoped JSON-compatible export and hard-delete cleanup of encrypted framework state are also verified. Core run and accounting records are retained. The live probe exposed and fixed use of unsupported `find_one()` on jvspatial's transaction handle; session collision/lifecycle lookups now use the supported `find()` API. Activation uses legacy `ChatThread.updated_at` as its compare-and-set token and writes an incremented Harness generation and new timestamp. The targeted PostgreSQL contract suite passes all 5 tests; see `task-02.2-step-store.md`, `task-02.3-session-cleanup.md`, and WP-06.4 evidence. Public export API and configurable retention policy remain package-level work.
