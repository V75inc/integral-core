# Substrate use cases

These scenarios explain the common foundation. They are patterns to qualify in the intended installation, not claims that every domain App ships with Core.

| Scenario | Substrate contribution |
|---|---|
| Team request review | Typed records, states, relations, comments, intentional roles |
| Evidence-backed decisions | Linked source records, attachments, provenance, review outcomes |
| Connected delivery | Separate collections with explicit relationships and lifecycle |
| Restricted supporting detail | Resource boundaries and authorized relation presentation |
| App generation | Inspectable package/model artifacts, validation, installation, active definition |
| External assistance | MCP capabilities under scope and policy |
| Repeated synchronization | Connector identity, deduplication, conflicts, attribution |
| Safe schema evolution | Drafts, impact checks, supported migrations and status |
| Recoverable work | Leases, effect identity, checkpoints, outbox and reconciliation |

A useful acceptance flow opens the resulting records and compares browser, API, and agent-visible facts. Include denied and invalid paths as well as happy paths. See the [user guide](../user-guide/README.md) and [qualification](../ops/QUALIFICATION.md).
