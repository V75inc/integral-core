# Development direction

Integral's next work should strengthen a coherent shared foundation rather than accumulate domain-specific shortcuts. This roadmap orders outcomes without inventing release dates.

## Qualify the present foundation

Close current provider, BYOK, approval, isolation, browser, artifact, and recovery matrices on identified candidates. Keep CI, local full tests, PostgreSQL contracts, packaged UI, and deployment acceptance separate. Address narrow-screen conversation usability and other observed experience defects with browser evidence.

## Complete governed durable interaction

Qualify native durable chat admission, interruption, replay, cancellation, current-permission checks, and final transcripts. Expand shared-worker operation only when process-local state and user journeys have been accounted for.

## Complete bounded work

Build the dedicated approved-mandate admission and complete physical/tool authority, shared limits, child lineage, reconciliation, and authenticated controls. Keep it non-runnable until these pieces work together. Synthetic budget tests are not an unattended outcome.

## Improve generative application delivery

Make design, package construction, active-definition compilation, migration, dependency delivery, review, and result readback increasingly consistent. Preserve external App portability and Core neutrality.

## Broaden useful integration

Qualify concrete native and MCP connectors, retrieval backends, attachment processing/scanners, and host configuration. Publish support claims from actual service/adapter evidence.

## Refine the experience

Make names, views, relationships, sources, review status, and recovery understandable to ordinary users. Expand application and facet experiences without inventing another authority plane.

The [qualification guide](../ops/QUALIFICATION.md) determines what can be promoted. The [white paper](WHITE_PAPER.md) explains the wider ambition.
